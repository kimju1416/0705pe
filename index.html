성취기준

상
직접 만들어 실행한다
교실·교무실의 불편함을 스스로 발견해 도구를 기획하고, AI와 함께 만들어 끝까지 완성·배포해 동료 교사와 나눈다.

좋은 프롬프트는 육하원칙으로

막연하게 말할수록 결과가 엉뚱해집니다 — 6가지를 채울수록 원하는 앱이 나옵니다

누가 WHO
사용자가 누구인지
체육 교사가 / 중학생 학생이 / 학부모가
언제 WHEN
어떤 상황에서 쓰는지
체육대회 당일 / 수업 중 / 측정 완료 후
어디서 WHERE
어떤 기기·환경에서
스마트폰에서 / 체육관 스크린에서 / PC에서
무엇을 WHAT
만들 기능·데이터
토너먼트 대진표를 / PAPS 결과를 / 점수를
어떻게 HOW
작동 방식·흐름
팀 수 입력 → 자동 생성 / 사진 찍으면 자동 입력
왜 WHY
만드는 이유·해결할 문제
매번 손으로 그리는 게 너무 오래 걸려서

바로 코딩하지 말고 먼저 PM 역할을 해줘.
좋은 PRD를 만들기 위해
필요한 질문을 하나씩 해줘.

질문이 끝나면 아래를 작성해줘 :
1. 완성된 PRD
2. 화면 설계
3. 기능 명세
4. 데이터 구조
5. 개발 프롬프트

체육 교사의 현실

학생 동기 저하
"자 이제 스쿼트 20개 하세요" → 흐지부지
경쟁·피드백·성취감 없으면 학생은 대충 함

PART 05

AI는 이것을 할 수 없다.

🏃 뛰어주는 것
100m를 0.01초 빠르게 달려주는 건 AI가 아니라 학생 자신의 두 다리다. 체력은 데이터로 대체되지 않는다.
🤝 넘어진 친구를 일으켜주는 것
운동장에서 함께 넘어지고, 손 내밀고, 다시 일어서는 경험이 체육 수업의 본질이다.
💧 땀 흘리는 것
플랭크 30초의 고통을 AI는 측정할 수 있지만, 느낄 수는 없다. 그 고통을 이겨낸 게 성장이다.
⭐ 이기는 기쁨, 지는 배움
시합에서 지는 순간의 감정, 이기는 순간의 환호 — AI는 그 순간을 기록할 뿐이다.

  • 직접 몸을 움직인다

용어사전 (1/2) — 개발·도구 용어
바이브코딩 Vibe Coding코드를 직접 작성하지 않고 AI에게 말로 설명해서 프로그램을 만드는 방식. Andrej Karpathy가 2025년 처음 사용.
프론트엔드 Front-end사용자가 직접 보고 클릭하는 화면. HTML(구조)·CSS(디자인)·JS(동작) 세 가지로 구성.
백엔드 Back-end서버에서 돌아가는 두뇌. 데이터 저장·계산·외부 연동 담당. 주로 GAS가 이 역할.
GAS Google Apps Script구글이 제공하는 무료 서버 스크립트. 시트·드라이브·Gmail과 연동, 교사 앱 백엔드로 최적.
HTML웹페이지의 뼈대를 만드는 언어. 버튼·입력칸·텍스트 등 화면 요소를 정의.
CSSHTML에 디자인(색상·크기·배치)을 입히는 언어. 앱의 시각적 스타일 담당.
JavaScript웹에서 동작(클릭·계산·화면 전환)을 처리하는 언어. 앱 핵심 기능 부분.
CDN Content Delivery Network외부 라이브러리를 URL 한 줄로 불러오는 방식. 설치 없이 단일 HTML에 적합.

API앱과 앱이 대화하는 창구. Gemini API·날씨 API 등 외부 기능을 내 앱에 붙여 쓰게 해줌.
MCP Model Context ProtocolClaude가 외부 서비스(드라이브·캘린더·슬랙)를 직접 조작하게 하는 연결 규격. 지시만 하면 됨.
프롬프트 PromptAI에게 내리는 지시·요청 문장. 육하원칙을 담을수록 정확한 결과가 나옴.
GeminiGoogle이 만든 AI. 이미지·문서를 읽고 텍스트를 추출(OCR)하는 기능이 강해 PAPS 자동 입력에 활용.
MediaPipe구글이 만든 AI 자세 인식 라이브러리. 카메라로 관절 위치를 실시간 파악, 스쿼트·플랭크 카운터 구현.
GitHub PagesGitHub에 HTML을 올리면 무료로 웹사이트가 되는 서비스. 프론트엔드 전용 앱 배포에 최다 사용.
NetlifyHTML을 드래그앤드롭으로 올리면 즉시 배포되는 클라우드. 자동 HTTPS·전 세계 빠른 속도.
OCR Optical Character Recognition이미지·사진 속 글자를 자동으로 읽어 텍스트로 변환. PAPS 결과지 사진 → 자동 입력에 활용.
